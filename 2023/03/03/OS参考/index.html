1. 概述

操作系统分类

单道程序设计（uniprogramming）：CPU 只能同时处理一个单独程序。 多道程序设计（multiprogramming）或多任务处理（multitasking）：当一个程序（作业）被中断需要等待某些事件发生时，CPU可以切换到另一个可以立即运行的程序（作业）。

分时系统：允许多个用户通过终端同时访问系统，共享CPU时间，操作系统以时间片为单位，轮流为每个终端用户服务，提供了较好的交互性。

  • 关注周转时间。（见 2.5 调度方案指标）

批处理系统：计算机系统对一批作业自动进行处理的技术，它不具有交互性，而是为了提高CPU的利用率而提出的一种操作系统。计算机操作员将作业组织成批，提交给操作系统，由操作系统控制它们自动运行。（解决 I/O 远慢于 CPU，造成资源闲置的问题）

  • 关注吞吐量，更少的上下文转换和更多的进程处理时间。
  • 分类
    • 单道批处理：内存中仅有一道作业，无法充分利用系统中的所有资源。
    • 多道批处理：在内存中同时存放多个作业，一个时刻只有一个作业运行，这些作业共享CPU和外部设备等资源。

硬件保护

两种 CPU 状态（进程运行的状态） 内核态：运行操作系统程序，操作硬件。可以执行特权指令。 用户态：运行用户程序。只能执行普通指令。

用户态到内核态的切换：

  • 系统调用 System call：用户态进程主动要求切换到内核态的一种方式，通过系统调用申请使用操作系统提供的服务程序完成工作
  • 外围设备的中断：外围设备完成用户请求后发出中断信号，CPU 将暂停下一条指令的执行并转到内核态处理中断
  • 异常

内核态到用户态的切换：设置程序状态字PSW

2. 进程管理

2.1 进程

  • 进程是什么

    • 一个正在执行的程序
    • 一个正在计算机上执行的程序实例
    • 能分配给处理器并由处理器执行的实体
    • 由一组执行的指令、当前状态和相关系统资源表征的活动单元

  • 进程与程序的区别：

    程序（Program） 进程（Process）
    储存在硬盘中的代码和静态数据 动态的实例：
    code + data + heap + stack
    一个程序可以创建多个进程 一个进程是一个独立的实体

进程的用户地址空间（user space）

进程控制块（PCB）

一个数据结构，由 OS 内核创建并维护，储存了一个进程的属性集合。 Process table 存储了所有的 PCB。

PCB 中包含的一些典型元素：

  • 进程标识符
  • CPU 状态信息
    • 寄存器数据（如：程序计数器 PC）
    • 栈指针
  • 进程控制信息
    • 调度信息：进程状态、优先级、等待的事件等信息
    • 使用的内存（内存指针）、I/O 状态信息、打开的文件等信息
    • 指向下一个 PCB 的指针

进程映像

包含了用户程序、用户数据、栈和属性（PCB）的集合

2.2 进程状态

二状态模型


只包含 运行态（Running） 和 非运行态（Not running）：一个进程要么在执行，要么未执行。 由此，需要维护一个队列，存储未运行的进程，以等待执行时机。 队列以轮转（round-robin）方式运作：每个运行态进程有一定的执行时间限制，时间到后切换至非运行态，加入队列尾。

五状态模型



就绪态（Ready）：进程已经做好执行的准备，但因为处理器有限且有其他进程正在执行，故处于等待执行的状态。
阻塞态（Blocked）：进程在某些事件发生前不能执行。比如 I/O 操作完成的事件。
新建态（New）：进程刚刚被创建，OS 还未把它加入可执行进程组。通常是 PCB 已经创建但还未加载到内存中的进程。
退出态（Exit）：OS 从可执行进程组中释放的进程。可能因为它自己停止或者因为某种原因被取消。

队列： 有一个就绪队列（Ready queue），等待运行的程序在此队列中。

  • 模型（a）中，只有一个阻塞队列，所有进入阻塞态的进程将被加入此队列。但这意味着阻塞队列中的进程可能在等待不同的事件，当事件发生时，操作系统需要扫描整个队列以选出在等待此事件的那些进程。
  • 模型（b）中，对每个事件都有一个阻塞队列。事件发生时，队列中所有进程切换至就绪态，加入就绪队列。

七状态模型


挂起态（Suspend）： 之所以需要挂起态，是因为有可能内存中所有进程都被阻塞，在等待某事件（如 I/O，因为它比处理器慢得多)。这时内存已满，新创建的进程无法进入。 这时，可以把未运行的进程换出内存，移到磁盘中，来腾出空间给新的进程。

  • 阻塞/挂起态：进程在外存中，并且在等待一个事件。
  • 就绪/挂起态：进程在外存中，但只要载入内存就可执行。

操作系统更倾向于挂起阻塞态进程而非就绪态进程。然而，如果释放内存的唯一方式是挂起一个就绪态进程，则就绪态进程会进入就绪/挂起态。 阻塞/挂起态进程在等待的事件发生后也会进入就绪/挂起态。 挂起操作即使在有可用内存时也可能会发生。

2.3 线程

线程是使用 CPU 的最小单位。 由上文的讨论，进程具有以下两个独立的特点：

  • 有资源所有权
  • 是可执行、被操作系统调度和分派的实体

其中，可执行、可被分派的实体单位部分称为线程（或轻量级进程）， 同时还拥有资源所有权的单位称为进程。


使用多线程的好处：线程间的切换和数据通信的开销非常低

  1. 相比于单线程：
    • 保持响应：即使程序的一部分模块被高耗时的操作阻塞，它的其他模块还能继续运行。
    • 多核优化：在多核架构的计算机中，可以同时在不同的处理器中运行多个线程来加速。
  2. 相比于多进程：
    • 资源共享：不同的线程都共享同一块地址空间。
    • 节省开销：创建进程比创建线程慢很多。

线程控制块（TCB）

TCB中包含的属性：

  • 线程标识符
  • CPU 状态信息
    • 寄存器数据
    • 栈指针
  • 线程控制信息
    • 调度信息：线程状态、优先级、等待的事件等信息

一个 PCB 中包含一个或多个 TCB。 一个进程中的每个线程都有一个单独的控制块和单独的栈。所有线程共享进程的状态和资源。


线程的实现方式


  1. 用户级线程（User-Level Threads, ULT） 管理线程的所有工作都由应用程序完成，内核意识不到线程的存在。
  2. 内核级线程（Kernel-Level Threads, KLTs) 管理线程的所有工作都由内核完成，应用级没有线程管理代码，只有一个到内核线程的 API。
  3. 混合型线程（Combined-Level Threads, ULT/KLTs)

2.4 进程间通信（Inter-Process Communication，IPC）

独立进程：不会影响其他进程，也不会被其他进程影响。 协作进程：反之。

实现 IPC

  1. 共享内存方式 通过内存访问来获取信息，在用户数据同步、写数据的互斥性方面需要更加谨慎。 以这种方式通信的相关进程必须解除访问彼此内存的限制。

  2. 信息传递方式 提供两个操作函数：send() 和 receive()。 又细分为两种方式：

    • 直接传递： 建立一对一的联系，直接互相发送数据。
    • 间接传递： 发送的数据需要经过中转点（如邮箱）才能到达对方。 可以是多对多的。 “邮箱” 可以由 OS 或进程管理。

    信息传递过程中可以选择：

    • Socket：直接交换字节流。
    • RPC（Remote Procedure Call）：远程调用函数。

同步性

信息的发送和接收可以是阻塞式的（同步），或非阻塞式的（异步）。

  • 阻塞式发送：发送方发送信息后被阻塞，直至消息被接收方（或中转点）接收。
  • 非阻塞式发送：发送方发送消息后继续正常运行。
  • 阻塞式接收：接收方等待消息，否则一直被阻塞。
  • 非阻塞式接收：接收方接收消息后继续正常运行。如果此时没有消息接收则返回空。

2.5 进程调度

在进程状态变更时（如从running切换到其他状态）采用的调度方案（决定哪个进程进入running状态）。

分类

  1. 长程调度（Long-term Scheduling） 决定将哪些进程加入进程池中。
    • 控制多进程并发的程度
  2. 中程调度（Medium-term Scheduling） 决定将哪些进程从内存中（部分）移入磁盘中。
    • 可以释放内存空间，一定程度控制并发的进程数
  3. 短程调度（Short-term Scheduling） 决定 CPU 执行哪个可执行（就绪态）进程。
    • 短程调度发生得非常频繁
    • 必须顾及效率问题


实现过程

上下文切换（有时也称做进程切换或任务切换）：是指 CPU 从一个进程或线程切换到另一个进程或线程。“上下文”是指某一时间点的 CPU 寄存器、PC（程序计数器）的内容。在切换时系统应该保存这个进程的当前状态。

  • 上下文切换只能发生在内核态中。
  • 需要消耗较多的处理器时间。

进程调度的实现：

  • 调度决策器 Scheduler：根据算法制定调度策略
  • 分配器 Dispatcher：执行调度所需的实际工作：
    • 上下文切换
    • 跳转到程序指定的执行位置

调度的性能衡量指标：派遣延迟（Dispatch Latency），是从一个执行中的进程切换到另一个并且开始执行之间的时间间隔。由以下三方面决定：

  • 调度决策所需时间
  • 重新启用中断所需时间
  • 上下文切换时间

2.6 并发性：互斥、同步

并发的进程 - 同时/交错执行的进程（线程） 并行（parallel）：在同一时刻，有多条指令在多个处理器上同时执行。所以无论从微观还是从宏观来看，二者都是一起执行的。

并发（concurrency）：在同一时刻只能有一条指令执行，但多个进程指令被快速的轮换执行，使得在宏观上具有多个进程同时执行的效果，但在微观上并不是同时执行的，只是把时间分成若干段，使多个进程快速交替的执行。

对于并发的进程，同步用于在几个进程间协调工作。分为：

  • 互斥（Mutual Exclusion）
    • 一定程度上限制进程对数据的访问（如：一个资源同一时间只能被一个进程访问）
    • 用于保持数据（在不同进程视角中）的一致性
  • 条件同步（Condition Synchronization）
    • 等待一个事件的发生（在某个事件发生之前进程不继续执行）
    • 用于保持一系列操作的先后顺序

一些并发相关概念 原子操作：一系列不可被外部打断（如中断）的动作，该动作的具体实现细节对外不可见。这种操作可以保证其中的指令序列作为一个组整体执行。

临界区（Critical Section，C. S. ）：一段代码，在这段代码中进程将访问共享的资源。 不能同时有多于一个进程处于临界区。

死锁（Deadlock）：几个进程因每个进程都在等待其他进程做完某件事才能执行，都被卡住。

活锁（Livelock）：几个进程都一直在响应其他进程而不断改变自身状态，但不能执行有用的工作。

临界区算法设计需要满足的条件：

  • 保证互斥性
  • 若临界区空闲，则允许进程进入
  • 想进入临界区的进程等待时间有限

纯软件实现的弊端：

  • 使用了忙等待（busy waiting）：如果其他进程在临界区内，则用循环卡住这个进程。这很浪费 CPU。
  • 如果代码没有按原本的顺序执行则会出错。 而编译器或者处理器很可能会因为优化而调整代码执行的顺序。

互斥：基于硬件的实现

  1. 禁用中断: 在进入临界区时完全禁用中断，在退出时再启用，这样可以完全避免抢占，从而完整执行完整个临界区的内容。 不是个好方法：

    • 给予进程太高的权限，凌驾于操作系统之上。操作系统对 CPU 的调度将失效。
    • 如果进程在临界区内出错，没有补救措施。
    • 如果临界区内的执行依赖某些外部中断，则出错。
    • 只禁用一个处理器的中断，在多处理器时还是有问题。

    但是简单并能保证互斥性，在单处理器操作系统的内核中常被使用。

信号量（Semaphore）

由系统实现的用于同步操作的工具 用阻塞（Blocking）操作代替忙等待。临界区满时其他想进入的进程将被设于阻塞的状态，节省 CPU 资源。

除了初始化操作和两个操作信号量的函数，信号量不能被其他方式改变，且对外部不可见。

信号量的分类 分类方式 1

  • 二值信号量：只能取 0 和 1 两值的信号量（初始化时），但允许取负数值（即可以卡住多个进程，放进等待队列）。 在信号量为 1 时调用 semSignal 的行为是未定义的。 用于实现互斥和同步
    • 互斥：初始化为 1 认为临界资源只有一个。
    • 同步：初始化为 0 在需要同步的点处才将信号量设为 1。这样在其中一进程到达该点前，其余进程不会越过该点。
      • 例：进程 A 在 a 点处想要往下执行，必须等进程 B 执行到 b 点。则设置一个初值为 0 的信号量，A 在 a 点 semWait，B 在 b 点 semSignal。
  • 多值信号量：可以取任意整数值 用于实现有限并发

分类方式 2

  • 强信号量：队列使用 FIFO 调度方式的信号量
  • 弱信号量：队列使用其他调度方式的信号量

互斥信号量总结：

  • 只要有多个同类型进程，就需要互斥信号量
  • 有多个信号量的情况下，需要先调用某个信号量的 semSignal 再调用其他信号量的 semWait，保证占用信号量访问权时，其他信号量的资源可用。

信号量的缺点：

  1. 易读性差： 要了解对于一组共享变量或者信号量的操作是否正确，必须通读整个程序。
  2. 不利于修改和维护： semWait 和 semSignal 散布于程序各处，程序的局部性很差。
  3. 正确性难以保证： 对信号量的操作代码都是用户编写的，系统很难有效管控它们。一旦出现逻辑错误，很容易出现死锁等现象。

管程（Monitor）

一种抽象数据类型，用于把分散在各进程的临界区集中起来管理，用高级语言书写。在进程访问临界资源时，只需调用对应的管程中的过程（procedure）。对资源使用的同步、互斥问题完全由管程解决。 类似于一个类，只有几个公有函数供外部调用，其他的数据都是私有的。在这些函数里实现临界区的互斥功能

定义：

  • 由局限于自己内部的若干共享数据结构和所有访问这些共享数据的过程所组成的软件模块
  • 必须满足以下管程的属性：
    • 共享性：一个进程只有调用管程内的过程才能进入管程，访问管程内的共享数据。
    • 安全性：管程的共享数据只能由该管程的过程存取，不允许进程或其他管程来直接存取，一个管程的过程也不应该存取任何非局部于它的数据。
    • 互斥性：在任一时刻，共享数据的进程可访问管程的管理该共享数据的过程，但最多只有一个调用者能真正地进入管程，而任何其他调用者必须等待，直到访问者退出。

分类： 有可能同时有多个进程在管程中出现：由于一个进入管程的进程可能会执行等待操作，这时管程的使用权将被释放，以便其他进程使用。如果后面进入管程的进程释放了之前等待的进程，则此时管程中有两个进程。 依据对这种情况的处理方法分类：（设进程 P 唤醒了之前等待的进程 Q）

  • Horse 管程：Q 先执行，P 等待 Q 执行

    • 入口等待队列（等待进入已被占用的管程的进程队列）
    • 紧急等待队列（在管程内部执行等待操作的进程被加入此队列）

    紧急等待队列的优先级高于入口等待队列

  • MESA：Q 等待 P 继续执行

  • Hansen，并发 Pascal：规定唤醒操作为管程中最后一个可执行的操作

  • 退出所有发生死锁的进程
  • 备份进程状态，一旦发生死锁，所有死锁进程回退到最近备份的状态 （但有可能同样的死锁还会再发生）

  • 选定一个进程把它所需的所有资源一个个抢占，直到无死锁

  • 死锁预防给 OS 施加了较强限制条件，损害了系统性能
  • 但实现简单

3. 内存管理

3.1 实内存

内存分配: 连续分配方式（分区分配方式，Partitioning）

  • 单一连续装配 只能用于单用户、单任务的操作系统 简单把内存固定地分为用户区和系统区。

  • 固定分区
    静态分区，系统启动的时候已经把内存划分好。分成若干个固定大小的连续区域，每个区域中只装一道进程。进程执行时，不会改变存储区域。 （✔）易于实现，系统开销小 （✘）分区较大而进程较小时，仍然浪费空间；分区数量固定，限制并发

    • 分区大小相等或不等：


    • 数据结构：
      • 分区表：记录每个分区的分区号、起始物理地址、大小、使用状态
      • 进程表：记录每个进程在哪个分区、进程名、进程大小
    • 分区分配算法：
      • 大小相等分区：没有特别的算法。都一样，随便放即可
      • 大小不等分区：
        • 每分区一个进程队列
        • 单一全局进程队列

  • 动态分区
    进程执行时才为它分配一个大小恰好的分区。分区都是动态的，编号也可变。 会产生外部碎片，有时需要通过压缩来整体移动所有进程，把碎片集中成大块一点的连续内存区域。

    • 数据结构：

      1. 分配分区表：保存已被分配的区域
      2. 空闲分区表：保存内存中的空闲区域
      3. 空闲分区链：链表，以每个空闲分区为元素，指针指向下一个空闲分区

    • 分区分配算法：

      • 最佳适配 Best-fit
        每次分配最小且能满足要求的分区
        • 在主存利用率上最优，但会产生大量内存小碎片
      • 首次适配 First-fit
        从头（最小地址处）开始找到第一个能满足要求的分区
        • 分配算法简单
        • 优先利用低址部分，保留了高址处的大空闲区
        • 最实用，实际操作系统中用得较多
      • 下次适配 Next-fit
        从上一次分配的位置开始找到第一个能满足要求的分区
        • 能使空闲分区分布均匀
        • 会导致缺乏大的分区
      • 最坏适配 Worst-fit
        每次从最大的空闲分区中分割一部分拿来用
        • 能使剩余部分的空闲空间不至于太小，对中小型作业有利

      使用频率：First-fit > Best-fit > Next-fit



  • 伙伴系统（Buddy System）

内存不足时的策略

  1. 内存紧凑（Memory Compaction）
    把分散的小空闲块合并成一个大空闲块
    • 数据先读出内存，再写入内存，开销大，基本没有现代 OS 使用
  2. 覆盖（Overlapping）
    把进程所需内存空间划分成一个固定区和多个覆盖区，主程序放在固定区，依次调用的子程序都放在同一个覆盖区（同一个进程内覆盖）
    • 在早期的单道连续存储管理中使用，现在也不用了
  3. 交换（Swapping）
    把内存中暂时不能运行的进程或进程所需要的程序和数据，调出到外存上
    • 整体交换（进程交换）：以整个进程为交换单位
      • 把外存分为：
        • 文件区（存放文件，采用非连续分配方式）
        • 交换区（存放换出的进程，采用连续分配方式）
      • 数据结构和分区分配算法均与动态分区类似
      • 置换策略
        • 换出时：选择处于阻塞状态且优先级别最低的进程作为换出进程
        • 换入时：找出“就绪”状态但已换出的进程，将其中换出时间最久的进程作为换入进程
    • 部分交换：以页或段为交换单位（页面交换/分段交换），将在虚拟内存部分提及

3.2 虚拟内存

虚拟内存技术使得比内存大的程序也能运行：将进程部分装入内存，部分装入外存，运行时访问在外存部分则动态调入。

重定位

物理地址（实地址，绝对地址）： 数据在内存中的实际位置，可直接寻址 逻辑地址（虚拟地址）： 当前数据的访问地址（与被分配的内存中的物理地址无关） 不能直接利用逻辑地址读取内存信息，需要经过地址转换得到可由机器直接寻址的物理地址，这一过程称为地址重定位

  • 相对地址 – 相对于某些已知点的存储单元（逻辑地址的特例） 如：用户程序在编译、汇编后形成的目标代码。其中的地址都是相对地址（将某一地址作为首地址 0 ）

分页

页
将一个进程的逻辑地址空间分成若干固定长度的块，这些块称为页。（对应一块虚拟地址）

页框
物理内存中与某页对应（大小相同）的固定长度的可用块（对应一块物理地址） 一个进程的若干页可以被放在并不连续的页框中。

页内碎片
进程的最后一页通常装不满一块，剩余的不可利用空间称为页内碎片

页表
每个进程一份，储存进程中的页与页框对应关系的表（即：虚拟地址到物理地址的映射表）。 一个页表在内存中连续存储（查页表时被拿来直接当地址使用的逻辑页号是连续的）。 PTBP 寄存器存放页表的起始物理地址。 页表项（PTE，Page Table Entry）是页表中的一条数据。

  • 进程的一页可能被映射到某个页框中，这表示它在物理内存中。
  • 这一页还有可能未被映射到某个页框中，这时发生缺页中断（page fault）。这一页应当在之前的某个时刻被置换出内存，被存储在外部存储中。

地址变换机构
  1. 当前进程的整个页表放在 CPU（MMU）的高速寄存器中
    • 页表必须要比较小
    • 速度快

  2. 当前进程的整个页表放在内存中
    • 设置页表基址寄存器 PTBR (Page-Table Base Register)，指向内存中的页表位置
    • 额外增加一次内存访问，速度减半

  3. 部分页表放在高速缓冲区中，其余部分放在内存中
    • 设置关联寄存器组（快表） TLB（Translation Look-aside Buffer）存放最近用过的页表项
    • TLB 未命中时才访问内存
    • 目前 OS 中使用最多的方案

段

  • 通常按照程序逻辑将程序划分成若干段

工作集：，表示进程在虚拟时刻 的过去 个虚拟时间单位中访问的页的集合。

4. I / O

I / O 设备

一种主要的分类方式

  • 块设备：可以编址，以固定大小的块为 I/O 存储基本单位，每个块可以被独立访问
    • 如硬盘、CD、磁带等
  • 流设备：不能编址，逐字节接收数据
    • 如鼠标、键盘、网络、打印机

CPU - I / O 通信

I / O 地址空间模式

I/O 功能的地址集合称为 I/O 空间。包括：

  • 所有设备寄存器
  • 内存中用以映射设备的数据缓冲区

地址空间模式：

  • 独立于内存 I/O地址空间与内存地址空间相互独立，对I/O地址空间的访问需要用特殊的I/O指令。
  • 完全映射到内存空间 I/O寄存器映射成内存的一部分，可以用内存访问语句来读写I/O设备寄存器。
  • 混合模式

I / O 通信模式

  1. 可编程 I / O
    由软件轮询（Polling）： 进程等待 I/O 时，使用忙等待的方式：CPU 持续检测 I/O 请求是否被满足
    • 以字节为基本处理单位：CPU 与 I/O 设备之间每次传送一个字节的数据
    • 很浪费 CPU 时间，现在基本不用
  2. 中断控制 I / O
    进程等待 I/O 时，CPU 继续执行（此进程或其他进程），I/O 响应时发出中断信号。
    • 以字节为基本处理单位
  3. 直接存储器访问（DMA）
    借助 DMA 控制器，数据直接从 I/O 设备送入内存。
    • 以数据块为基本处理单位：CPU 与 I/O 设备之间每次传送至少一个数据块
    • 相当于 DMA 控制器代替 CPU 不断轮询 I/O 设备，并把数据传输至内存。在传输完一个或多个数据块时（或者刚开始传输时）才需 CPU 干预

缓冲

缓冲的引入：

  • 缓和CPU与I/O设备之间速度不匹配的矛盾
  • 减少对CPU的中断频率，放宽对CPU对中断响应时间的限制。
  • 提高CPU和I/O设备之间的并行性

磁盘 I / O

磁盘结构




磁盘由一些盘片（Platter）组成，多个盘片垂直堆叠。
每个盘片上划分为一圈圈的磁道（Track），每个磁道由若干扇区（Sector）组成，并以一些缝隙隔开。一个扇区的大小通常为 512B（字节）。 所有盘片中，垂直对齐的那些磁道合称柱面（Cylinder）。
磁头臂用来控制磁头的位置，读取盘面上的数据。（读取某一柱面的数据）

扇区是磁盘中数据的最小存储单位，每个扇区中的数据包含：

  • 用于同步和确定位置的首部信息
  • 实际存放的数据
  • 用于纠错的尾部信息（ECC）

为增加文件存取效率，由多个扇区组成的逻辑单位“块”，是 I/O 操作（文件存取）的最小单位。大小通常为 4KB

磁盘布局

  1. 恒定角速度
    • 每条磁道上的扇区数量相等（长度不等，越外面越长）
    • 结构简单，但在外部的长磁道上浪费空间
  2. 多区记录（恒定线速度）
    • 扇区长度均相等
    • 数据密度大，但结构复杂，数据获取起来也相对复杂

磁盘性能参数

寻道时间 ：将磁头移动到目标磁道上所需的时间
旋转延迟 ：（磁头已经移动到目标磁道上后）目标扇区旋转到磁头位置所需的时间
存取时间 ：达到读/写位置所需时间，=寻道时间+旋转延迟
传输时间 ： 扇区数据传输时间

5. 文件管理

5.1 文件系统

文件

文件是长期存在的，储存在外存中，退出系统后文件不会丢失。 是 OS 对硬件资源的抽象：逻辑存储单元

文件支持的操作：
  • 创建 / 删除
  • 打开：进程将一个已有文件声明为打开状态，允许进程对这个文件进行操作（即：将文件属性和其在磁盘上的位置信息载入内存）
  • 关闭：进程关闭一个文件，不再能对其操作
  • 读取 / 写入
  • 重命名
文件结构：
  • 域
    基本的数据单元，包含一个值（类型没有要求） 相当于一条记录的一个属性。
  • 记录
    一组相关域的集合，可视为应用程序的一个单元。
  • 文件
    一组相似记录的集合，被用户和应用程序视为一个实体，可通过名字访问。
文件属性

由 OS 存储的，关于文件本身的数据。有时被称为文件的元数据（metadata）。 OS 维护 FCB（类似进程的 PCB），管理所有文件的信息。（见 5.2. FCB 或 inode）

文件组织

文件记录中的逻辑结构（文件内部的组织结构）

  1. 堆（Pile）
    数据按到达的顺序被收集，储存成一条记录（不定长）。堆文件没有结构，对记录的访问通过穷举查找进行。
    • 最简单的文件组织形式
  2. 顺序文件（Sequential）
    每条记录都使用固定的格式（定长），由相同数量、长度固定的域按特定顺序组成。 包含一个关键域，唯一地标识一个记录。 为减少数据更新时的延迟，新记录被放在一个单独的堆文件中，称为 日志文件 。它们会被周期性地批量更新，合并到主文件中。
    • 最常用的文件组织形式
    • 性能差，匹配关键域需要遍历文件
  3. 索引顺序文件（Indexed Sequential）
    在顺序文件的基础上，增加了一个用于支持随机访问的文件索引（提供快速查找的能力），以及一个溢出文件区域（类似于顺序文件中使用的日志文件，存储新记录）。
  4. 索引文件（Indexed）
    使用多索引的结构，可支持基于多种属性的查找。只能通过索引来访问记录。可以使用长度可变的记录，且记录的放置位置无限制。
  5. 直接文件 / 散列文件
    使用基于关键字的散列表。记录的长度是固定的。

5.2 文件系统的实现

记录组块

由于块是与磁盘进行 I/O 操作的基本单位 （见 4. I/O ）。文件中的每条记录需要组织成块的形式。

  • 定长组块
    使用定长的记录，若干完整的记录保存在一个块中。每个块的末尾可能有未使用的空间。
  • 变长跨越式组块
    使用变长的记录，并且填满每个块。对于跨越块的记录，通过一个指针连接。
  • 变长非跨越式组块
    使用变长的记录，但不跨越块。大多数块的末尾都会有未使用的空间。

文件分配

为文件在辅存中分配一系列的块来存储。

  • 预分配：在发出创建文件的请求时，声明该文件的最大尺寸并一次性分配它所需的块。
  • 分区：一组连续的已分配块。
  • 文件分配表（File Allocation Table, FAT）：记录在辅存中分配给每个文件的分区信息的数据结构。

对于文件分配的方法，需要考虑：是否预分配？分配给文件的分区大小如何？

文件分配方法

  • 连续文件分配（Contiguous allocation）
    创建文件时，给文件分配一组连续的块 在 FAT 中，记录每个文件的起始块和长度 需要时常执行压缩算法来释放磁盘中的额外空间。


  • 链式分配（Chained allocation）
    基于单个块，链中的每块都包含指向下一块的指针。 在 FAT 中，记录每个文件的起始块和长度。


  • 索引分配（Indexed allocation）
    每个文件都额外储存一个索引块，FAT 只需要储存这个索引块的位置： 在这个索引块中记录此文件的每块在辅存中的位置。

    • 基于固定块的索引分配：
      文件以块为单位分配并记录在索引块中。


    • 基于长度可变分区的索引分配：
      文件以一系列连续块为单位分配，索引块中需要记录这些块的起始位置和长度。


空闲空间管理

已分配的空间需要被 OS 管理。同样地，空闲的空间也需要被管理，在分配新的空间的时候才能知道哪些空间是空闲的。

磁盘分配表（Disk Allocation Table, DAT）：类似文件分配表 FAT，但用于管理空闲空间

空闲空间管理技术
  • 位表（Bitmap）
    每个块的空闲情况用一 bit 存储（1 - 空闲，0 - 占用）。
    • 简单，高效。但占用很大的空间。
  • 链接空闲区（Linked List）
    类似文件分配中的链式分配技术：每个空闲块存储指向下一个空闲块的指针。
  • Grouping
    类似文件分配中的索引分配技术：每隔 n 个块就有一个块中存储了一个索引表，记录在它之后的 n 个空闲块的位置（它之后的第 n 个空闲块又存储了索引表，这样可以一直往下找）。
  • Counting
    类似文件分配中的连续分配技术：在 DAT 中存储每段连续空闲区的起始位置和长度。

文件控制块（FCB），或 索引节点（inode）

在 Unix 中，一个 FCB 被称作 inode（index-node） 单个 inode 对应单个文件，存储与这个文件有关的属性等信息。 所有的 inode 也被存储在磁盘的特定块中，称为 inode table。
